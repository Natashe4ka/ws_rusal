# Изменения и проверка

## Окружение

Используйте Python 3.12, editable-установку и закреплённый submodule KUKA:

```bash
git submodule update --init --recursive
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

## Порядок изменений

1. Опишите воспроизводимый сценарий и ожидаемый результат.
2. Разделяйте изменения физических параметров, алгоритмов и оформления.
3. Для изменений физики сохраняйте seed, профиль, шаг, решатель, исходное
   состояние и критерии приёмки. Не заменяйте отрицательные результаты
   положительными без нового измерения.
4. Добавляйте тест, если изменение затрагивает поведение или исправляет ошибку.
5. Выполните `ruff format --check src/rusal_mujoco src/rusal_motion_planning scripts`,
   `ruff check src/rusal_mujoco src/rusal_motion_planning scripts` и `python -m pytest -q`. Для тяжёлого опыта отдельно укажите число
   перенесённых деталей, строгие проходы, предупреждения и причину остановки.

Во время исполнения положения свободных грузов не задаются напрямую.
Начальная компоновка, восстановление состояния, копия планировщика и рендер
имеют отдельные назначения и должны оставаться отделены от физической динамики.

## Исходники и результаты

Не добавляйте в Git виртуальные окружения, каталоги colcon, машинные пути,
сохранённые траектории и видео. Небольшие тестовые фикстуры размещайте рядом
с тестами с описанием происхождения. Сводные результаты — в `docs/validation/`.
Права и уведомления сторонних моделей сохраняются без изменений.

## Pull request

Опишите проблему, итоговое поведение, параметры проверки и известные ограничения.
Не заявляйте промышленную надёжность по одному seed или локальному стенду.
