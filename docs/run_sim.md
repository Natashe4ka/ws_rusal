# Запуск симуляции

Все команды выполняются из корня checkout после editable-установки пакета.
Модели KUKA загружаются через Git submodule или `scripts/bootstrap_robot.py`.

## Компактная навалка

```bash
./run_sim.sh --config configs/hybrid_foam_jaws.yaml --count 5 --seed 42 --speed 4
./run_heap20.sh --speed 4
./run_batch10.sh --speed 4
./run_cross24.sh --speed 4
```

Профили `hybrid_batch10` и `hybrid_cross24` задают разброс
380–420 × 190–210 × 30–50 мм и 12–14 кг. Паллет имеет размеры
1200 × 800 × 180 мм. Исходные состояния генерируются гравитацией, без стенок
и принудительного выравнивания деталей.

Проверяется связность контактов и равновесие навалки: контрольные точки
смещаются не более чем на 5 мм за окно проверки, кинетическая энергия
не превышает 0,001 Дж, проникновение — 1 мм. Не прошедшая проверку навалка
не используется в цикле.

## Перекрёстная укладка

Профиль `configs/hybrid_cross24.yaml` разрешает три слоя: длинная ось детали
чередуется X → Y → X. Геометрический планировщик учитывает реальные размеры
деталей и фактические границы уже уложенных тел. Число деталей по слоям
заранее не фиксируется. Для партии seed=42 сумма площадей равна 1,93597 м²,
что больше двух плоскостей паллеты (1,92 м²) даже без зазоров.

```bash
./run_cross24.sh --headless --out results/logs/cross24_check
```

Последний сохранённый опыт: 11/24 размещений, 8 в первом слое и 3 во втором.
Остановка зарегистрирована из-за контакта `tool_case` с `jaw_pad_right`.
Одна ранее размещённая деталь к моменту финального аудита вышла за край паллеты.
Сценарий доступен для исследования этой ошибки; завершение всей партии
не гарантируется. Подробности: [результаты](experimental_results.md).

Если исходное направление маркированного торца недоступно, параметр
`pallet.allow_marking_conflict: true` разрешает разворот курса на 180°
с сохранением оси слоя. В отчёт записывается `marking_conflict`. Для строгого
направления торца установите `false`. Видимость торца внутри плотной укладки
отдельно не подтверждена.

## Параметры CLI

```bash
./run_sim.sh --scenario compact --count 5 --seed 42 --mode hybrid
./run_sim.sh --scenario compact --count 5 --surface ribbed --mode vacuum
./run_sim.sh --scenario stack --count 12
./run_sim.sh --source results/logs/heap10_detailed --mode hybrid
```

- `--count` относится к генерируемым сценариям `compact` и `stack`.
- `--source` выбирает сохранённую навалку; число тел определяется снимком.
- `--surface mixed|smooth|ribbed` задаёт начальное направление широкой грани
  до физического осаждения, а не итоговую позу после оседания.
- `--headless` отключает окно; `--out` задаёт префикс выходных файлов.
- `--max-attempts` ограничивает количество попыток, включая неудачные.

`stack` формирует контролируемые стопки и позволяет проверять укладку отдельно
от доступности деталей в случайной навалке.

## Сохранение и продолжение

Результаты содержат XML модели, NPZ интеграционного состояния, CSV траекторий
и сил, JSON конфигурации, попыток и итогового аудита. В профиле 24 деталей
контрольная точка записывается после каждого принятого размещения.

```bash
./run_sim.sh --resume results/logs/cross24_check --headless --out results/logs/cross24_continued
```

Продолжение допускается из состояния с освобождённым грузом. Прерванный подход
проверяется дополнительно: вакуум должен быть выключен, инструмент не должен
контактировать с чушкой. Состояния с удерживаемым грузом требуют отдельного
контролируемого восстановления и не принимаются обычной командой `--resume`.

## Потеря удержания

При срыве инструмент освобождается и отходит, затем ожидается успокоение
детали. Устойчивое приземление может быть принято при наличии опоры, соблюдении
границ паллеты и допусков XY ≤25 мм, Z ≤20 мм, курса ≤5°, наклона ≤8°,
проникновения ≤1 мм. Факт срыва остаётся в журнале, строгий критерий качества
не становится положительным. Иначе деталь остаётся приоритетом повторного
подбора. Лимит — пять срывов на деталь.

## Запись и управление окном

```bash
./run_sim.sh --config configs/hybrid_foam_jaws.yaml --count 5 --headless --video results/videos/compact5.mp4
```

Запись включается только параметром `--video`. Начальные и конечные заставки
не добавляются. Для повторного рендера сохранённых состояний используется
`scripts/render_recorded_sim.py`.

Клавиши: `Space` — пауза, `=` / `+` и цифровой `+` — увеличение скорости,
`-` и цифровой `-` — уменьшение, `Esc` — выход. `--speed` принимает значения
до 8. Тяжёлая контактная сцена может рассчитываться медленнее реального времени.

Для GUI на программном Mesa-рендерере `run_sim.sh` задаёт
`LIBGL_ALWAYS_SOFTWARE=1`; для headless по умолчанию используется `MUJOCO_GL=egl`.
Эти переменные можно переопределить перед запуском.

## ROS и MoveIt

Автономный `sim` использует собственные имитаторы восприятия и управления.
ROS-мост доступен отдельно:

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/rusal-sim ros
```

Мост публикует состояния и обслуживает команды вакуума, губок и суставов,
а также action `FollowJointTrajectory`. Интеграционный smoke-тест MoveIt
проверяет короткое суставное движение; полный MoveIt Pick-and-Place не реализован.

Развёрнутый URDF хранится в исходниках, поэтому обычная симуляция не требует
xacro. Для явного обновления URDF из закреплённого upstream:

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/python -c 'from rusal_sim.robot import expand; expand()'
```
